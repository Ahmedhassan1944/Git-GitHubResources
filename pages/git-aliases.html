Git Aliases

Speed up your workflow with short, memorable shortcuts for the commands you use most.

What is a Git Alias?

An alias is a user-defined shortcut that expands to a longer Git command (or series of commands). It lives in your global ~/.gitconfig and is invoked exactly like any native Git sub-command.

Why do they exist?

Because you spend a lot of time typing the same long commands. An alias removes friction, reduces mental overhead and makes your workflow feel instant.

Benefits of using aliases

  • 🚀 Faster command entry
  • 🔁 Consistency across machines (when shared via dotfiles)
  • 📚 Self-documenting shortcuts (e.g. git cm = “commit-message”)
  • ⚡️ Less typing → fewer typos

Alias syntax

git config --global alias.<newAlias> "<command>"

git config – Git's configuration tool
--global – store it for the whole user
alias.<newAlias> – the shortcut name
"<command>" – the full command to run

Define a few common aliases

# commit with a message
git config --global alias.cm "commit -m"

# short status
git config --global alias.st status

# branch overview
git config --global alias.br branch

# checkout a branch (exchange)
git config --global alias.exchange checkout

Using them

# Commit
git cm "Initial commit"

# Status
git st

# List branches
git br

# Checkout a feature branch
git exchange feature/login

Common mistakes

  • ❌ Forgetting quotes around commands that contain spaces.
  • ❌ Over-aliasing – turning every command into an alias makes the cheat-sheet unreadable.
  • ❌ Using aliases that clash with existing Git sub-commands.

Best practices

  • ✅ Keep aliases short (< 3 characters) and memorable.
  • ✅ Prefix with a unique character when in doubt (e.g. gco for checkout).
  • ✅ Document them in your README or dotfiles.
  • ✅ Group related aliases in a single `gitconfig` section.
  • ✅ Test each alias after creation.

Professional workflow with aliases

  1. 🔧 Setup – run the "Define a few common aliases" block once per machine.
  2. 💡 Daily work – use git cm, git st, git br throughout the day.
  3. 🚦 Review – run git lg (log graph) before merging.
  4. 🧹 Cleanup – git unstage or git reset via alias.
